# Feature Specification: 《叫我大掌柜》经典五合一小游戏集

**Feature Branch**: `001-legend-multi-games`  
**Created**: 2026-01-23  
**Status**: Draft  
**Input**: User description: "帮我自动生成《叫我大掌柜》的五款经典小游戏：一马当先、硕果累累、大开眼界、庄园拼图、水管接通"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 游戏中心选择与切换 (Priority: P1)

用户进入应用后可以清晰地看到五款不同类型的小游戏入口，并能随时从当前游戏返回主菜单切换到另一款小游戏。

**Why this priority**: 作为集合型项目，多游戏的导航和基础入口是最核心的需求，决定了用户能否访问到所有内容。

**Independent Test**: 用户启动应用，主界面显示五个按钮。点击任意按钮进入对应游戏，在游戏界面点击“返回”按钮能回到主界面。

**Acceptance Scenarios**:

1. **Given** 应用处于主菜单界面, **When** 用户点击“一马当先”图标, **Then** 系统加载并启动划线路径小游戏
2. **Given** 用户正在进行“硕果累累”游戏, **When** 用户点击左上角的“返回主菜单”图标, **Then** 会话进度被保存并跳转回主选择界面

---

### User Story 2 - “一马当先”核心玩法 (Priority: P1)

用户通过在屏幕上划线连接起点和终点，引导骏马在不触碰障碍物的情况下到达目的地。

**Why this priority**: 这是《叫我大掌柜》中最具代表性的划线益智玩法。

**Independent Test**: 用户划动手指产生路径线条，释放后马匹沿线移动。马匹碰到边缘或障碍物提示失败，到达终点显示通关。

**Acceptance Scenarios**:

1. **Given** 关卡中有墙壁和悬崖, **When** 用户划出的线经过墙壁区域, **Then** 引导马匹移动时触发碰撞失败逻辑
2. **Given** 用户划出了一条安全路径, **When** 马匹移动到终点旗帜位置, **Then** 系统播放通关动画并解锁下一关

---

### User Story 3 - “硕果累累”合并消除 (Priority: P1)

用户控制水果落下的位置，让相同等级的水果碰撞并合成为更大等级的水果，最终目标是合成大西瓜。

**Why this priority**: 合并类游戏具备极高的用户粘性和成瘾性，是该系列的核心组成部分。

**Independent Test**: 用户点击屏幕，顶端水果下落。两个相同的蓝莓碰撞变成一个草莓。水位线超过顶部红线则游戏结束。

**Acceptance Scenarios**:

1. **Given** 容器中有两个相同的葡萄, **When** 一个葡萄落在另一个上方使其接触, **Then** 两个葡萄消失并生成一个体积更大的柠檬
2. **Given** 容器内水果堆积到顶部界限, **When** 持续时长超过3秒, **Then** 系统进入结算界面显示当前得分

---

### User Story 4 - 游戏进度全局管理 (Priority: P2)

系统自动保存每款小游戏的关卡进度、历史最高分以及已解锁的成就。

**Why this priority**: 增加用户长期玩的动力，提供基础的成就感回馈。

**Independent Test**: 用户在“庄园拼图”通关第5关后关闭应用。再次打开应用并进入该游戏，系统默认停留在第6关。

**Acceptance Scenarios**:

1. **Given** 用户在“大开眼界”刷新了记录, **When** 用户返回主菜单或重新启动应用, **Then** 主界面对应图标上方的“最高记录”实时更新

---

### User Story 5 - “庄园拼图”空间逻辑 (Priority: P2)

用户将散落的庄园农作物或建筑碎片拖入指定的阴影区域，碎片必须完整且不重叠地填满轮廓。

**Acceptance Scenarios**:

1. **Given** 玩家选中一块碎片, **When** 拖拽到目标点且距离小于 50 像素, **Then** 碎片自动吸附并变色。

---

### User Story 6 - “大开眼界”细节对比 (Priority: P2)

用户在两张高度相似的图片中找出 5 处细微差异，支持双指缩放。

**Acceptance Scenarios**:

1. **Given** 图片包含缩放状态, **When** 点击正确差异位置, **Then** 差异点被醒目圆圈标记并计分。

---

### User Story 7 - “水管接通”管网构建 (Priority: P2)

用户通过点击旋转混乱的水管，使水源从进水口流向出水口。

**Acceptance Scenarios**:

1. **Given** 路径已形成通路, **When** 最后一段水管旋转到正确角度, **Then** 播放流水动画并完成关卡。

---

### Edge Cases

- **断网处理**: 在游戏过程中切换网络或断网，由于是纯单机小游戏，应确保流程不中断且本地保存正常。
- **内存溢出**: 在“硕果累累”中水果极其密集时，应通过对象池优化确保低端设备不卡顿。
- **非法路径**: 在“一马当先”中，若起始点和终点被封闭路径完全隔断，系统应能识别关卡配置合法性。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 系统必须包含五个子游戏：一马当先、硕果累累、大开眼界、庄园拼图、水管接通。
- **FR-002**: “一马当先”模块必须支持动态路径生成及碰撞体实时检测。
- **FR-003**: “硕果累累”模块必须实现基于物理引擎的圆周碰撞合并逻辑及溢出判定。
- **FR-004**: “庄园拼图”模块必须支持托放式交互，并将不同形状的板块完美贴合进入指定轮廓。
- **FR-005**: “大开眼界”模块必须支持图片缩放查看功能，并在指定时间内标记出所有细微差异点。
- **FR-006**: “水管接通”模块必须支持点击旋转管件，并实时判定起点到终点的连通性状态。
- **FR-007**: 必须提供统一的 UI 状态管理，用于在五个子游戏和主菜单间切换而无内存泄漏。
- **FR-008**: 数据存储采用混合模式：核心进度优先保存在本地 LocalStorage，并预留接口支持手动同步至后端 API 以确保数据跨端可靠性。

### Key Entities _(include if feature involves data)_

- **GameSession**: 记录单次游戏的运行时状态，包括当前分数、连击数、剩余时间等。
- **LevelConfig**: 静态配置数据，定义每款游戏的关卡难度、障碍物位置、目标分数等。
- **UserProgress**: 持久化实体，存储用户的解锁进度、最高得分及获得奖励。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 用户在不同小游戏间切换的加载时间（从点击到进入游戏画面）必须控制在 2 秒内。
- **SC-002**: 在主流移动设备浏览器上运行，所有游戏必须保持 60 FPS 的流畅度。
- **SC-003**: 任务完成率：95% 的用户能够无需教程指引完成每款游戏的第一关（通过记录首次通关时长 < 180s 作为指标）。
- **SC-004**: 数据可靠性：在非正常关闭应用（杀死进程）的情况下，最近一次完成的关卡记录保存成功率达 100%。

## Assumptions

- 默认采用移动端优先的设计，输入方式以点击、划动、拖拽为主。
- 关卡内容通过 JSON 配置文件进行外部化管理，方便后续热更新或扩展。
- 暂不考虑多人联机或实时对战排名。
- 数据同步接口（API）的具体协议将在技术实施规划阶段定义。
