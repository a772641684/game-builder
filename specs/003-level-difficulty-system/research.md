# 研究与决策 (Phase 0)

本文记录了关卡生成算法与难度梯度的研究结论。

- [ ] 研究各小游戏的关卡生成算法 (FR-001)

- [ ] 设计里程碑解锁逻辑 (FR-005)
- [ ] 确定倍率奖金算法 (FR-006)

## 研究结论

### 1. 关卡生成算法 (Procedural Content Generation)

| 游戏名称     | 生成策略                             | 确保可玩性 (Solvability)                 |
| :----------- | :----------------------------------- | :--------------------------------------- |
| **抓娃娃**   | 物品随机分布，随难度增加缩小物体间距 | 物理引擎边缘检测                         |
| **层层叠**   | 平台宽度缩小速度，偏移量随机化       | 无特殊需求                               |
| **涂鸦跳跃** | 基于 Y 轴的高度区间生成平台          | 限制两平台间距 < 角色跳跃极限 (约 250px) |
| **点线交织** | 基于“图相关”算法生成随机锚点         | 预制 50 组模板，随机应用偏移旋转         |
| **弹弹球**   | 砖块矩阵生成的稀疏度 (Density)       | 确保底部第一排前 50 关不生成砖块         |
| **泡泡龙**   | 权重随机生成的棋盘布局               | 洪水填充检查联通分量，色相不跨 3 种      |

### 2. 难度曲线 (Difficulty Curves)

采用 **线性增长 + 阶段性爆发** 模式：

- `Difficulty = 1 + floor(Level / 5) * 0.2 + (Level % 5) * 0.05`
- 主要影响参数映射表 (符合 SC-002 <= 15% 要求)：

| 难度阶段      | 系统难度系数 (Difficulty) | 物理参数增长上限 (相对于基准/上一阶段) |
| :------------ | :------------------------ | :------------------------------------- |
| Level 1 - 10  | 1.0 - 1.5                 | 初始基准值                             |
| Level 11 - 20 | 1.6 - 2.0                 | 上一阶段 + 12%                         |
| Level 21 - 30 | 2.1 - 2.5                 | 上一阶段 + 10%                         |

- 主要影响参数：
    - `ObjectSpeed`: 基础速度 \* Difficulty

    - `SpawnInterval`: 基础间隔 / Difficulty
    - `PrecisionLimit`: 允许误差 / Difficulty

### 3. 里程碑与奖励 (Progression & Rewards)

- **存档点**: 每 10 关为一个存档点。一旦达到，失败后从该关卡继续，但不获得“全胜奖金”。
- **倍率系统**:
    - 基础倍率 = 1.0
    - 每关增加 0.1x (最高 3.0x)
    - 奖励积分 = `BaseScore * ComboMultiplier * DifficultyMultiplier`

## 决策记录

- **决策 1**: 使用 `Math.seedrandom` (或自定义 LCG) 确保相同关卡 ID 生成的布局一致。
- **决策 2**: 放弃全随机（Pure RNG），采用“参数化模板”，尤其是针对《点线交织》。
- **决策 3**: 难度参数化，控制脚本不再直接写入数值，而是从 `DifficultyManager.getParams(gameType)` 获取。
